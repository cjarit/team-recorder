## 3. Workstreams

### A. Identity, install, reinstall

**Root fix:** sign every build with the same identity so TCC keeps the grants.

| Tier | Cost | Fixes TCC re-grant on upgrade | Fixes Gatekeeper "Open Anyway" dance | Enables auto-update later |
|---|---|---|---|---|
| A1 Self-signed code-signing cert (Keychain Access, 10-year validity, same cert for every build) | 0 | Yes (per developer reports — PoC gate) | No | Partially (GitHub check only) |
| A2 Apple Developer ID + notarization | $99/yr | Yes | Yes | Yes (Sparkle-ready) |

`[D-1]` Owner picks the tier. A2 reverses the 2026-05-26 decision; it is the owner's call, not mine.

Either tier means **one last re-grant** when users move from the ad-hoc v1.2.4 to v2.0 (identity changes once). Tell users this in the release note; after that, upgrades keep permissions.

**Install surface** (independent of tier): a `.dmg` with drag-to-Applications (standard, no script). No `.pkg` — an unsigned pkg hits the same Gatekeeper wall and adds a preinstall script to maintain. The app self-heals on first launch after a version change instead:

1. Detect `CFBundleShortVersionString` ≠ `UserDefaults.lastRunVersion`.
2. Stop a watcher left over from the old version (PID file), clear stale `status.json`.
3. Keep `.env` (RECORDING_DIR), `trackedCalendarIds`, Launch-at-Login.
4. Re-check permissions silently; show the setup window **only** for the ones actually missing (today it reopens the whole guide).

**Uninstall… menu item** (in-app version of `make uninstall`): confirm dialog → stop watcher → remove runtime state → reveal the recordings folder → move the app to Trash. Recordings never touched.

**Setup guide trims:** Calendar step becomes opt-in ("Skip" is the default when the org blocks calendar — the owner's case); Screen Recording and Mic stay required.

**PoC gate (A, per LESSONS #1):** build → grant → rebuild → reinstall → grant must survive, **plus** a control run with ad-hoc that reproduces the loss. One `/Applications` install per test round.

### B. Control UI

Inventory of today's menu: status line, warning line, Start/Stop Recording, Start/Stop Watcher, Recover, Recordings Folder (path/open/change), Last recording, Tracked Calendars submenu, Permissions submenu (3 panes + calendar status), Setup Guide, Launch at Login, Quit — 15 items, 3 submenus.

`[D-2]` Surface:

| Option | Looks like | Fits |
|---|---|---|
| B1 Popover from the menu bar icon (Control-Center style), menu stays for Quit / Setup / Uninstall | 1Password / Dropbox panel | Fast daily control, glanceable status, recordings list |
| B2 Real window with sections (Status · Recordings · Settings · Permissions) | Setup Guide pattern, already AppKit | More room, more clicks |

Recommendation: B1 for daily use + the existing menu reduced to 5 items. Implementation: SwiftUI views hosted in `NSPopover` (`NSHostingController`), macOS 14 floor allows it; the app stays AppKit, Python stays the brain, `status.json` stays the contract.

Content sketch (non-binding): header = state + meeting name + elapsed; two live level bars (system / mic); big Start/Stop; "Recent recordings" (last 10: name, duration, size; reveal, play, rename, trash); footer = folder, calendars, mic device, permissions status, update check.

Design flow: owner sketches in Figma (frugal path, owner is the designer) → I implement with `swift-expert` → owner reviews on a real build.

New data the UI needs: live levels. Recorder writes a small `levels.json` sidecar (RMS sys/mic, mic-alive flag) every second into App Support; app reads it. Python loop untouched. Also enables a watcher-side alert "mic silent for 60 s while recording" (the BT-stuck case that was invisible for an hour on 2026-09-29).

Manual rename of "Teams Meeting …" files: deferred since v1.2.0 (DECISIONS) → lands in the recordings list.

**Existing PoC (2026-10-08, another session, uncommitted):** `menu-bar/Sources/TeamRecorderBar/PopoverView.swift` (SwiftUI, system colors only, 6 states incl. light/dark) + `StatusBarController.swift` (+114 lines: left-click → popover, right-click / "More…" → the old menu). Watcher, recorder, `status.json` untouched. Builds; not yet run on-device. Owner's first read: contrast looks weak in the offscreen renders. Assessment: renders use an opaque grey background instead of popover material, so most of the greyness is the render, not the design; two real issues regardless of background: orange title on orange-tint error card, and the "Recover Recorder…" button should be the prominent control. Rule: judge colour on a real build, one variable at a time.

**Sequencing consequence:** every rebuild re-prompts all three TCC grants while the app is ad-hoc signed. Do Phase 1 (stable identity) **before** on-device popover iteration, so UI test rounds stop costing a re-grant each.

### C. Audio quality (echo)

Step 1 — locate, not fix. Questions for the owner `[D-4]`: who hears it (call participants live, or whoever plays the file)? speakers or headset? เสียงซ้อน (doubled, delayed) or เสียงก้อง (hollow)? did it start after 29 Sep? Ask the reporter for one file; run the same cross-correlation.

Step 2 — candidates ranked by blast radius:
1. Headphones guidance (zero code) — if bleed only appears with speakers.
2. Offline echo reduction inside `--mixdown`: system track is a perfect reference; NLMS adaptive filter on the mic track before summing. Touches no live path, no AVAudioEngine, no Bluetooth risk. Validate on a known-bleed file.
3. Hollow/narrowband voice = Bluetooth HFP mic quality — no filter fixes it; the fix is device choice (mic picker in the UI).
4. `setVoiceProcessingEnabled(true)` on the input node — Apple AEC, but ducks Teams audio for the user. Last resort, PoC with ducking level `min`.
5. SCK `captureMicrophone` (PoC B, macOS 15+) — primarily the BT-hang fix from NOW.md; whether it applies AEC is unknown. Fold its test into the same PoC round. `[D-5]` macOS floor: anyone still on 14?

### D. Lightness

Measure before cutting: idle CPU and RSS of watcher + app over 10 min (`ps`/`top` sampling), bundle size, launch time. Act only on a number. Safe deletions regardless: `Setup.command`, `Start Recorder.command`, `_backup/`, `slide-assets/` if unused, Terminal keyboard `1`/`2` controls. No main-loop refactor.

### E. Versioning and "keep the current version"

`[D-6]` Reading A (recommended): git/release — `v1.2.4` tag and zip stay on Releases; v2.0 is built on branch `v2`, merged to `main` at release; a v1.2.x hotfix branch can be cut from the tag if ever needed. Reading B: side-by-side install on one Mac — needs a new bundle id, App Support dir, PID files; two watchers would both record the same meeting and two SCK clients interrupt each other (confirmed bug class, v1.2.2). Not recommended.

## 7. Risks

- Self-signed tier: Gatekeeper dance remains; "Open Anyway" on macOS 15+ is the worst first-run step we cannot remove without Developer ID.
- Monthly Screen Recording re-approval on Sequoia+ (if it applies here) is outside our control.
- SwiftUI-in-popover: file-watcher refresh must stay on main; reuse `StatusBarController`'s `DispatchSource` path, do not add a second watcher.
- Echo fix in `--mixdown` is offline DSP written by us; validate against a known answer (LESSONS #2) — synthesize bleed by mixing a delayed copy of the system track into a clean mic track, then measure removal.
