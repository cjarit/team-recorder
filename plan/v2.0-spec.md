## 0. Agent brief — read before touching anything

**Invariants (never violated by any agent):**
- `teams_recorder_v2.py` main loop: bug fixes only. No restructuring, no async, no new threads. New behaviour goes into the Swift recorder, the Swift app, or a post-stop helper.
- Python stays the brain; the app reads `status.json` (+ the new `levels.json`), never logs.
- One ScreenCaptureKit client per recording. No second `recorder` process while one is recording. PoC B tests run with the watcher stopped.
- Tuned constants (`POLL_INTERVAL`, `STOP_GRACE`, `MIN_DURATION`, `UDP_MEET_THRESH`, `DISK_*`) unchanged.
- Recordings are never deleted by software. "Skip" means move to a subfolder.
- Thai inline comments are kept. No new code comments, no docstrings beyond the existing pattern.
- Define each value once (schema, paths, thresholds live in one place and are referenced).

**Verification rule:** every deliverable ships with the check named in §5 run and its raw output quoted. "I think it works" is not a result. A subagent's diff is reviewed by tracing one iteration of its caller.

**Who does what** (one routing per task, cheapest capable first):

## 1. Functional requirements (EARS)

IDs: `FR-<area>-<n>`. Areas: ID identity · UPG upgrade · POP popover · WIN window · LVL levels · MIC mic picker · UPD updates · UNI uninstall · PB PoC B · ECHO echo · VAD speech detection (PENDING) · AUD audio source option (PENDING) · DOC docs.

### 1-A Identity (D-1: self-signed certificate)

- **FR-ID-001** The build system shall sign `TeamRecorderBar.app` and the bundled `recorder` binary with one self-signed code-signing certificate named `Team Recorder Signing` from the login keychain, replacing ad-hoc signing in `make menu-bar`.
- **FR-ID-002** When the certificate is absent, `make menu-bar` shall stop with the message `run: make cert` and shall not fall back to ad-hoc.
- **FR-ID-003** `make cert` shall create the certificate once (code-signing EKU, 10-year validity) and shall be idempotent (second run: "already exists", exit 0).
- **FR-ID-004** The built app's designated requirement (`codesign -dr -`) shall reference the certificate and bundle identifier `com.team-recorder.menu-bar`, and shall not contain `cdhash`.
- **FR-ID-005** The bundle identifier, app name, and install path `/Applications/TeamRecorderBar.app` shall remain unchanged from v1.2.x.

### 1-B Upgrade path and reinstall

- **FR-UPG-001** When the app launches and `CFBundleShortVersionString` differs from the stored last-run version, the app shall run the self-heal sequence: stop a watcher recorded in the PID file if its command line matches the bundled watcher, remove stale `status.json` / `recorder.pid`, write the new version, and continue without showing the Setup window unless a required permission is missing.
- **FR-UPG-002** While upgrading, the app shall preserve `.env` (RECORDING_DIR, AUDIO_INPUT_DEVICE_UID), `trackedCalendarIds`, Launch-at-Login state, and the recordings folder contents.
- **FR-UPG-003** When Screen Recording is not granted after an upgrade and a stale grant from the ad-hoc line may exist, the Setup window shall show the instruction "Remove the existing TeamRecorderBar row with − and add the app again" instead of the generic step.
- **FR-UPG-004** The Setup window shall allow the Calendar step to be skipped, and shall persist the skip so that Permissions rows and the popover do not show Calendar as missing afterwards.
- **FR-UPG-005** `make dmg` shall produce `dist/TeamRecorderBar-v<version>.dmg` containing the app and an Applications symlink; `make release` shall produce both the zip and the dmg.
- **FR-UPG-006** The version/settings store shall be `UserDefaults` unless the Phase 2 precondition check (`defaults read com.team-recorder.menu-bar` before/after one reinstall) shows values lost; in that case an App Support JSON file shall be used and this requirement updated.

### 1-C Popover (daily surface)

- **FR-POP-001** When the status item is left-clicked, the app shall show the popover; when right-clicked, the reduced menu (Setup Guide…, Uninstall…, Launch at Login, Quit) shall open. Quit shall not appear inside the Settings/Status window.
- **FR-POP-002** The popover shall render four states from `status.json`: Recording (state `recording`/`stopping`), Ready (`waiting`), Error (`error` or watcher not running with stale status), Paused (watcher not running by user choice).
- **FR-POP-003** In the Recording state the popover shall show meeting name (or "Name not found yet — looking at the Teams window" when the name is the placeholder), elapsed time, two level meters (system, mic) from `levels.json`, and a Stop Recording button.
- **FR-POP-004** In the Ready state the popover shall show a Start Recording Now control.
- **FR-POP-005** In the Error state the popover shall show the error reason from `lastError` and a prominent Recover Recorder… button; the card title shall use the primary text colour with an orange icon (not orange text on orange tint).
- **FR-POP-006** The popover shall show the Permissions rows only when at least one required permission is missing or when Calendar is neither granted nor skipped.
- **FR-POP-007** The popover shall show the last recording (name, saved time) with a reveal-in-Finder action, "Open Recordings Folder", and "Open Team Recorder…" (opens the window). File rename/delete shall not be offered in-app.
- **FR-POP-008** The popover shall follow system light/dark appearance using only system semantic colours and SF Symbols; no third-party UI dependencies.

### 1-D Settings / Status window

- **FR-WIN-001** "Open Team Recorder…" (popover) and ⌘, shall open one window with tabs Status · General · Calendars · Permissions; closing it returns the user to the popover-only mode.
- **FR-WIN-002** The Status tab shall show, from live checks, the same items as `make doctor`: watcher running/pid, recorder binary check, permissions ×3, disk free on the recordings volume, last recording, last error, app version, and a Check for Updates button.
- **FR-WIN-003** The General tab shall expose: recordings folder (change), Launch at Login, notify-on-save toggle, Microphone picker (FR-MIC), and the audio options (FR-AUD).
- **FR-WIN-004** The Calendars tab shall host the existing Tracked Calendars allowlist; the Permissions tab the three permission rows with open-pane actions and the Calendar "Skipped" state toggle.
- **FR-WIN-005** Every action available in the v1.2.4 menu shall be reachable from the popover or the window (inventory from the Haiku task is the checklist).

### 1-E Levels sidecar and mic-silent alert

- **FR-LVL-001** While recording, the recorder shall write `levels.json` (schema §4) atomically every 1 s into App Support.
- **FR-LVL-002** When `levels.json` is older than 3 s, the popover shall render the meters as "no data", never as frozen bars.
- **FR-LVL-003** When `micAlive` has been false for 60 consecutive seconds while state is `recording`, the app shall send one notification "Your mic isn't being captured — others' voices are still recorded" per recording session.
- **FR-LVL-004** Level computation shall not run on `micQ` and shall not block the stdin protocol queue.

### 1-F Microphone picker

- **FR-MIC-001** The General tab shall list input devices from `recorder --list-devices` with "Auto (system default)" first; selecting one shall write `AUDIO_INPUT_DEVICE_UID` to `.env` and restart the watcher when not recording.
- **FR-MIC-002** While recording, the picker shall be disabled with the note "Change after the current recording".

### 1-G Update check

- **FR-UPD-001** When the user clicks Check for Updates, the app shall query the GitHub Releases API for the latest `v2.*` tag, compare with the running version, and show "Up to date" or "v2.x available — Download" (opens the release page). No background polling, no auto-install.

### 1-H Uninstall

- **FR-UNI-001** When the user chooses Uninstall… and confirms, the app shall stop the managed watcher, remove `status.json`, PID files and `levels.json`, keep `.env` and recordings, reveal the recordings folder, move the app bundle to Trash, and quit. The confirmation shall state that recordings are kept and permissions must be revoked manually.

### 1-I PoC B gate (SCK microphone, macOS 15+)

- **FR-PB-001** The recorder shall offer a mic path using `SCStreamConfiguration.captureMicrophone`, selectable by build flag, honouring the same stdin protocol and output format as today.
- **FR-PB-002** The SCK mic path shall become the default only when the gate in §5 passes; otherwise the AVAudioEngine path remains the default and the flag ships off.
- **FR-PB-003** Where the SCK mic path is default, the AVAudioEngine path shall remain selectable via `MIC_PATH=engine` in `.env` for one release.

### 1-J Echo reproduction

- **FR-ECHO-001** The project shall include `scripts/xcorr.py` (moved from scratchpad) that reports, per 10-s window, the normalized cross-correlation and lag between the system and mic tracks of a dual-track recording.
- **FR-ECHO-002** When the reproduction (MacBook speakers + MacBook mic, 3-min meeting) yields median correlation > 0.3, v2.0 shall add a popover hint "Built-in speakers + built-in mic can echo in recordings — use headphones" shown while recording with that device pair, and a FAQ entry. Offline echo reduction is v2.1.

### 1-K Audio source option (approved 2026-10-08, modelled on Teams' device panel)

- **FR-AUD-001** The General tab shall show an Audio group: Microphone [Auto (system default) / device list] with a "Record my voice" toggle (default on; off = system audio only, mic track omitted), and the current system output device as read-only information.
- **FR-AUD-002** Where "Record my voice" is off, the recorder shall not open any input device.
- **FR-AUD-003 (research, v2.1)** "Auto" following the device Teams actually uses is desirable (incident setup: system input = MacBook mic while Teams used the headset, so the user's own voice was recorded from the wrong mic). Feasibility via CoreAudio "device is running somewhere" heuristic is unverified; not in v2.0.

### 1-L Post-recording speech detection (approved 2026-10-08)

- **FR-VAD-001** During `--mixdown`, the recorder shall compute `speechRatio` = fraction of 100-ms frames whose RMS exceeds −40 dBFS on the mixed signal, and write it to the sidecar `<file>.meta.json` (§4).
- **FR-VAD-002** When `speechRatio` < `kSpeechMinRatio` (initial 0.05, calibrated on existing recordings before shipping), the app shall move the file to `<RECORDING_DIR>/Empty/` and notify "No speech detected — moved to Empty". Files are never deleted.
- **FR-VAD-003** Files named "Teams Call (Short)" (< `MIN_DURATION`) shall **not** be moved by this rule; the existing short-call naming stays as-is (owner decision 2026-10-08).
- **FR-VAD-004** The threshold shall be calibrated on the 352 existing recordings: distribution of `speechRatio`, with "Teams Call (Short)" files and known test joins as the positive class; report false-move rate on real meetings before enabling.

### 1-M Docs

- **FR-DOC-001** README, `docs/user/*`, and `CLAUDE.md` shall describe two release lines (1.2.x macOS 14 bug-fix only; 2.x macOS 15+), the one-time permission re-grant on moving to 2.0, the stale-row instruction, the monthly Sequoia dialog (FAQ, one entry), and headphones guidance if FR-ECHO-002 triggers.

## 2. Non-functional requirements

- Floor macOS 15; both `Package.swift` on tools-version 6.0 with `swiftLanguageModes: [.v5]`.
- No third-party dependencies in either Swift package; app bundle growth ≤ 1 MB over v1.2.4.
- Idle CPU of watcher + app ≤ v1.2.4 baseline (measured in Phase 7); `levels.json` writes ≤ 1/s.
- Popover opens < 150 ms, window < 300 ms, on the owner's machine.
- `make test` stays green (136 passed, 3 skipped) plus new tests for any Python change.
- No secrets in the repo; the certificate's private key stays in the keychain, never exported into the repo.

## 3. Acceptance criteria (Given / When / Then)

- **AC-ID-1** Given a cert-signed build granted all three permissions, when the app is rebuilt and reinstalled three times, then `make doctor` reports all three granted each time without any System Settings interaction.
- **AC-ID-2** Given the same procedure with an ad-hoc build, when reinstalled once, then at least one grant is lost (control run proves the test can fail).
- **AC-ID-3** Given a Mac that has never held the certificate in its keychain, when a cert-signed build is granted, replaced by a newer cert-signed build, and launched, then all grants persist. (Fail → D-1 reopens.)
- **AC-UPG-1** Given v1.2.4 installed with a custom RECORDING_DIR and one tracked calendar, when v2.0 replaces it and launches, then the folder, calendar allowlist, and all 352 recordings are unchanged and the user is asked for permissions exactly once.
- **AC-POP-1** Given each of the four states injected via `status.json`, when the popover opens in light and dark mode, then the owner confirms readability on device (not from offscreen renders).
- **AC-LVL-1** Given a recording with the mic device removed, when 90 s pass, then exactly one mic-silent notification fires and meters show "no data" within 3 s of the recorder exiting.
- **AC-WIN-1** Given the Haiku inventory of 15 v1.2.4 actions, when each is attempted from popover or window, then all 15 succeed.
- **AC-PB-1** Given system input = MacBook mic and Teams mic = Bluetooth headset, when a Meet-now is joined and left with the SCK mic path, then stderr shows zero `MIC_GAP` > 0.5 s and `ffmpeg -f null` decodes the full duration with 0 errors.
- **AC-VAD-1** Given the calibration set, when the threshold is applied, then 0 real meetings would be moved and ≥ 90 % of known test joins would.

## 4. Interfaces introduced by v2.0 (single source of truth)

`levels.json` (App Support, written by recorder, read by app):
```json
{ "ts": "2026-10-08T14:32:10", "sysRms": -28.4, "micRms": -41.0, "micAlive": true, "micDevice": "AirPods Pro" }
```
`<recording>.meta.json` (next to the file, written by `--mixdown`, FR-VAD):
```json
{ "speechRatio": 0.37, "durationSec": 1821, "mixedAt": "2026-10-08T14:35:02" }
```
Makefile targets added: `cert`, `dmg`. `.env` keys added: `MIC_PATH` (`sck`|`engine`), `RECORD_MIC` (`1`|`0`).
Constants: `kSpeechMinRatio` (Swift), `kLevelsIntervalSeconds = 1`, `kLevelsStaleSeconds = 3`, `kMicSilentAlertSeconds = 60`.

## 5. Gates and error handling

| Condition | Detected by | Behaviour |
|---|---|---|
| Cert missing at build | `make menu-bar` | stop, print `run: make cert` |
| Teammate-condition cert test fails | Phase 1 | halt; reopen D-1 with the owner |
| `levels.json` unwritable | recorder | log once to stderr, keep recording |
| Update check offline | app | "Couldn't check — try later", no retry loop |
| `--mixdown` fails | existing behaviour | original kept; `meta.json` absent → no move |
| PoC B gate fails | Phase 5 | flag stays off; recorded in DECISIONS |
| Echo not reproduced | Phase 6 | FR-ECHO-002 dropped; logged |
